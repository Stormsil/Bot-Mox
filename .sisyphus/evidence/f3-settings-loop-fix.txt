F3 settings loop fix evidence
Date: 2026-03-03

Root cause
- `apps/frontend/src/pages/settings/ui/ThemeSettingsContainer.tsx` synchronized incoming `themeSettings` via `useEffect` and called `theme.applyThemeSettings(themeSettings)`.
- The effect was retriggered by unstable identity in the sync path (theme callback/object churn + equivalent settings payload), repeatedly applying the same settings and causing React nested updates (`Maximum update depth exceeded`).

Exact fix
- File changed: `apps/frontend/src/pages/settings/ui/ThemeSettingsContainer.tsx`
- Replaced direct effect dependency on `theme`/callback identity with a guarded sync:
  - store latest `theme.applyThemeSettings` in a ref (`applyThemeSettingsRef`)
  - compute serialized incoming settings key (`JSON.stringify(themeSettings)`)
  - skip apply when the serialized payload is unchanged (`appliedThemeSettingsKeyRef`)
  - reset guard when `themeSettings` becomes null
- Behavior preserved: same settings still apply when payload changes; repeated equivalent payload no longer retriggers re-entrant updates.
